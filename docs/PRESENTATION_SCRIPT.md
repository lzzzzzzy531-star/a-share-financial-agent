# 答辩讲稿

## 30 秒版本

这个项目是一个 A 股多智能体分析系统。用户输入一个自然语言问题后，Supervisor 会选择市场、财务和估值 Agent 分别处理。市场和财务数据来自 AkShare，DCF 估值由 Python 工具确定性计算，最后由综合层、报告层和 Dashboard Builder 生成 Streamlit 页面。项目重点是安全边界：完整价格序列和财务历史留在 Structured State，LLM 只看到经过裁剪的安全上下文，避免模型重新计算、编造或越界解释。

## 90 秒版本

这个项目解决的是金融分析 Agent 中常见的两个问题：一是多类任务混在一起时职责容易混乱，二是 LLM 容易基于不完整上下文做过度解释。

系统使用 Supervisor 先判断用户问题需要哪些能力。如果问题包含行情，就交给 Market Agent；包含财务指标，就交给 Financial Agent；包含 DCF，就交给 Valuation Agent。每个 Agent 只处理自己的职责范围。

数据层面，AkShare 返回的完整价格序列和财务历史会进入 Structured State，供 Dashboard 和确定性计算使用。但发给 Qwen 的 LLM Context 会被 sanitizer 裁剪，例如 Market 不发送完整 60 日价格序列，Financial 不发送完整 12 期财务历史。这样既能保留前端展示需要的数据，也减少模型误读和越界分析。

估值部分也做了边界控制。DCF 不让模型自己算，必须调用 Python 工具，根据用户提供的自由现金流、增长率、折现率、永续增长率和预测年数确定性计算。综合层也不重新计算任何工具结果，只基于安全观察做跨模块总结。

最后，系统增加了缓存、统一失败对象和 fallback。外部接口或模型失败时，页面不会整体崩溃，而是局部降级并保留可用模块。

## 3 分钟版本

这个项目是一个 A 股多智能体分析系统，目标不是直接给投资建议，而是展示一条更可控的金融分析链路。

首先是任务拆分。用户可以输入一个复合问题，例如“分析贵州茅台的市场表现和财务指标，并做 DCF 估值”。Supervisor 会根据关键词选择需要的 Agent。Market Agent 只负责行情表现，Financial Agent 只负责财务指标和基本面数据，Valuation Agent 只负责估值和 DCF 计算。这样可以避免一个大模型在同一个回答里混用职责。

第二是数据安全边界。系统里有两个通道：Structured State 和 LLM Context。Structured State 是应用内部状态，可以保存完整数据，比如 60 日价格序列、12 期财务历史和 5 年 DCF 预测序列。Dashboard 画图、趋势引擎计算都依赖这些完整数据。LLM Context 则是发给 Qwen 的上下文，只包含经过 sanitizer 裁剪后的字段和 Python 生成的客观描述。

例如，Market Agent 获取完整行情后，完整价格序列会保存到 Structured State，但不会发送给 Qwen。Financial Agent 获取财务历史后，完整 12 期历史用于 Dashboard 和趋势计算，但 Qwen 只知道历史范围和报告期数量。这样做的原因是：LLM 不应该拿长序列自行推断趋势、支撑压力、行业水平或风险等级。

第三是确定性计算。DCF 估值必须由工具完成，模型不能自行估算自由现金流，也不能自行计算企业价值。财务趋势也先由 Python 计算同比变化，再让 Qwen 生成摘要；如果摘要越界，就直接放弃。综合层如果出现未经授权模块、新数字或不合规表达，也会切换到 Python fallback。

第四是可用性。系统对 AkShare、网络接口、Qwen 调用、Dashboard 构建都做了异常处理。失败会变成统一失败对象，Dashboard 支持局部失败，不会因为一个模块挂掉而整页不可用。同时，股票解析、行情历史、财务快照和财务历史都有 TTL 缓存，减少重复请求。

最终结果通过 Streamlit 展示，包含市场表现、财务指标、历史趋势、DCF 估值、综合分析和最终汇总报告。这个项目的价值在于：它不是简单让模型“回答金融问题”，而是把数据、计算、模型解释和前端展示拆开，并为每一步设置边界。
